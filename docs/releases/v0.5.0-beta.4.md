# SC v0.5.0-beta.4

Windows x64 prerelease of the Electron/TypeScript application. Publication status
is tracked in the [README](../../README.md#release-status). SC v0.4.14 remains the
latest stable release while this beta is prepared.

## Downloads and setup

- `SC-Setup-v0.5.0-beta.4.exe`: installs for your Windows account, creates SC
  shortcuts and enables **Settings → Updates**. Administrator rights are not required.
- `SC-v0.5.0-beta.4.exe`: portable application; replace it manually for updates.
- `SC-v0.5.0-beta.4.zip`: the same portable EXE plus its original `README.txt`.
- `LICENSE.txt`, `THIRD_PARTY_NOTICES.txt` and
  `ThirdPartySources-v0.5.0-beta.4.zip`: SC's MIT license, dependency notices and
  upstream sources. Keep the notices with redistributed copies of the executables.
- `SHA256SUMS.txt`: checksums for all supplied assets. On Windows, compare an
  asset with `Get-FileHash .\SC-Setup-v0.5.0-beta.4.exe -Algorithm SHA256`.

Close an older SC instance before installation. On first launch, choose your API
service and enter its key. Setup saves the key without making a model request.
Your provider account needs model access and any required credits. The application
includes its runtime. The executables are unsigned; Windows may show an unknown
publisher or reputation prompt.

## Changes since the previous public application

- Electron/TypeScript application with a React interface and native Windows bridge.
- Per-user installer and explicit update download/restart controls. Portable builds
  remain available. Uninstall preserves encrypted settings.
- Service-aware first launch, grouped Settings, advanced model disclosure,
  focused validation and retained unsaved drafts.
- Update restart protection while Settings has unsaved edits, recovery after failed
  downloads, and guarded shutdown during early startup.
- Compatible encrypted settings migration, selectable response preferences and the
  Thorough, Balanced and DeepSeek Direct request pipelines.
- MIT licensing for SC project code, with separate third-party notices and sources.

The [user guide](../USER_GUIDE.md) describes controls, providers, privacy and updates.
Captures and typed questions are sent to the selected provider. SC keeps no
screenshot or answer history; provider retention policies apply. Recording
exclusion is best effort and the tray icon remains visible.

## Verification and limits

- Linux and Windows verification: **1,065 tests / 21 files**, types, lint and bundles.
- Windows: **31 native checks**, **8 vault interoperability cases / 136 legacy
  fixture checks**, and **16 Electron UI workflows**, none skipped.
- Packaged runtime: five duplicate launches, ten early-close relaunches and direct
  portable startup with development tools absent from PATH.
- Actual historical beta.3 → beta.4 local installer/update scenario: **22 checks**,
  including corrupt-download rejection and encrypted settings retention.
- Native fixture readiness: **120/120 accepted frames**, zero provider calls.
- Edge whole-monitor recording: all **24 phases** completed and received/saved
  output inspected. OBS saved output was inspected independently for **24 phases**;
  its automation report retains a final receiver-preview failure.

These are Windows 11 results from one VM. Fresh-account/machine, Windows 10,
mixed-DPI, other capture paths and representative live model quality remain open.
The exhausted 120-attempt DeepSeek campaign retained answer, canonical-validation
and extraction-fidelity failures; it does not establish a quality promotion gate.
Public GitHub update delivery has not yet been exercised. Detailed scope and
retained failures are in [verification](../VERIFICATION.md).
