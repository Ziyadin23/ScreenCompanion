# Documentation

This folder contains detailed public reference documents. Keep the root README a concise guide to using SC and the current release.

- Update documentation links after source moves and distinguish source-only organization changes from downloadable releases.
- Read [PUBLISHING.md](PUBLISHING.md) for distribution builds and GitHub releases.
- [USER_GUIDE.md](USER_GUIDE.md) owns detailed setup, controls, settings, privacy, and troubleshooting. [PIPELINE.md](PIPELINE.md) owns advanced configuration and request flow. [VERIFICATION.md](VERIFICATION.md) owns recorded checks and unfinished limitations; test fixture/runner commands remain in `tests/README.md`.
- Keep architecture/source ownership and agent behavior in the root and scoped `AGENTS.md` files. Summarize user essentials and link to the relevant reference from the README; keep configuration tables, benchmark counts, lab history, and the full source map in their reference files.
- Keep private VM/USB identifiers, lab accounts, snapshots, recordings, credentials, and unfinished local test steps in the parent workspace context, outside this repository.
