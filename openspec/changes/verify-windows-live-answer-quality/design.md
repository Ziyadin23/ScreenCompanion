# Design

## Context

See [proposal](proposal.md) and [existing lab procedure](../../../desktop/tests/lab/README.md). The selected issue names Windows beta.6; the issue branch starts at shared source `dede1d6` with beta.7 application code. That branch is the documentation owner, not automatically the executed candidate.

Retained beta.5 diagnostic evidence reports 6/8 strict passes and 13/120 charged contacts (two preflights and eleven diagnostic sends), with no frozen qualification candidate at that observation. Both Balanced diagrams failed only task-type fidelity despite correct canonical answers, displayed first lines and visual coverage. These are historical observations; the current guest registry has not been inspected for this issue.

## Goals / Non-Goals

Qualify the selected production/pipeline paths with independent strict grading and an explicit, cumulative request limit. A completed campaign report can record failure; a successful quality gate requires all 49 strict passes on one frozen executed identity. Never infer either from a plan, portable test, old diagnostic or targeted repeat.

This sampled DeepSeek matrix does not establish all-provider coverage, broader reasoning settings, real assessment behavior, packaged EXE parity, hotkey/typed-Send GUI coverage, recorder exclusion or beta.7 qualification. No default promotion, application fix, new allowance, merge or release is included.

## Decisions

### Candidate and execution prerequisites

Propose the unchanged beta.6 production sources associated with release tag `v0.5.0-beta.6` and the retained Windows beta.6 build receipt. Recover the exact source/native/harness snapshot in the existing private lab; compare production payloads with that receipt and record any harness-only differences explicitly. Preserve historical snapshots; never silently run beta.7 as beta.6. If a matching runnable beta.6 lab cannot be recovered, report the mismatch and obtain a candidate decision before freezing or spending.

After campaign approval, follow shared VM scheduling, inspect the latest private ownership/release record and acquire the headless Windows lab with fresh baseline/process/input/vault observations. Read and reconcile the fixed campaign manifest, ledger, results and locks against the retained post-diagnostic snapshot. An unexpected frozen candidate, extra charge, corruption or unresolved owner/attempt blocks execution; never reset, reconstruct or replace history to continue. Historical private qualification wrappers were explicitly blocked and include a retained execution-barrier finding; do not execute them as a current runbook. Prepare and independently review a current coordinator procedure before any registry write or live command.

Run the existing portable selftest, Windows native build and all twelve offline visual readiness cases on the recovered snapshot, with zero provider calls. Bind the native addon and exact Windows-entry runner using `node scripts/deepseek-tests.mjs --identity` after the final native build. Freeze the qualification identity once under the existing manifest contract; document source/native/executed identities privately. No subsequent source/config/native rebuild is allowed under that identity. Existing production pixel, foreground, geometry, crop and readiness checks remain required before paid sends; a stale frame stops the run.

### Representative matrix and proposed allowance

Use the existing `--plan` matrix, preserving its run IDs and order:

| Group | Coverage | Operations | Maximum contacts |
| --- | --- | ---: | ---: |
| Main | Six fixtures × plain/proctoring × Thorough/Balanced/Direct, Flash | 36 | 72 |
| Typed | Dependent and independent synthetic tasks × three modes, Flash | 6 | 11 |
| Translation | Synthetic proctoring text × three modes, Flash | 3 | 6 |
| Pro | Proctoring MCQ, Thorough and Balanced, Flash extraction/Pro answering | 2 | 5 |
| Fresh preflights | Flash production Direct contract and text-only Pro contract | 2 | 2 |
| **Total** | **One fresh qualification phase** | **49** | **96** |

Flash uses `deepseek-flash`, None reasoning, 2500 answer/6000 extraction output tokens. Pro uses `deepseek-v4-pro`, Low reasoning and 16000 answer tokens, without sending images to Pro. All cases use trusted standard mode and no fixed question region. The Pro preflight is text-only contract coverage, not image-capable Direct support. Fixtures include MCQ, multiple selection, numeric, code, a labelled rectangle and two ordered questions. Proctoring is only a synthetic layout with invented identity/static indicators and no monitoring integration.

Propose at most **96 new contacts**, including failed/interrupted reservations, inside the existing **120 total** ceiling. If current reconciliation confirms the historical 13, the proposed run ends at most at **109/120**, leaving eleven reserve contacts **unspent and outside this execution approval**. Initial/diagnostic calls never repeat or replenish. No automatic retry/fallback, reserve repeat or second qualification is authorized. Insufficient remaining phase/global allowance blocks the phase. A preflight failure stops its invocation; inspect and checkpoint before further spending.

The two required retests, `main-diagram-plain-balanced` and `main-diagram-proctoring-balanced`, are included in the 49. Each allows two contacts. Run the full fixed qualification order; no extra diagnostic run is needed. If execution stops before reaching either retest, report that criterion incomplete instead of silently using reserve.

After approval and readiness/freeze, the existing command is `node scripts/deepseek-tests.mjs --live --phase qualification --candidate <frozen-identity>` from the recovered Windows desktop directory. The placeholder must be replaced by its verified Windows identity. This document does not authorize executing that command yet.

### Grading and evidence

Grade canonical primary answers, production-formatted first lines, displayed ordered coverage, extraction component booleans, visual diagram/label coverage and exact call budgets independently. Direct/typed cases retain the lab's applicable/null extraction semantics. Preserve the original task-type failures and compare each Balanced diagram's new `taskTypes` and full extraction/visual grades. Never loosen expected types or substitute correct answers for extraction evidence.

Record per-case and per-stage latency, contact counts, token/cache usage and provider-reported monetary cost when available. Aggregate median/range latency and known usage separately by model/mode; report missing usage/cost as unknown. Do not infer dollars from request count, absent prices or unavailable billing metadata. Capture only allowlisted technical metadata; keys, captures, task/response text and raw exception bodies remain in memory. Record actual exit, unresolved reservations, all failed attempts and process/input/profile/vault postflight independently of the quality result.

Publish candidate-specific results in verification and update W3 plus this task owner. Distinguish completed-with-failures, interrupted and all-49-passed. A failed/partial campaign leaves issue #8 open and uses a partial PR reference. Successful closure additionally requires both named retests and the complete evidence/report/review criteria. No source correction or additional paid repeat is implied by failure.

## Risks / Trade-offs

- Current registry may differ from historical 13/120 → reconcile before accepting allowance arithmetic or freezing.
- Old blocked coordinator preparations may appear executable → retain them and review a fresh procedure against current evidence.
- Flash/Pro account access or model behavior may have changed → fresh bounded preflights; retain failure without fallback.
- A correct displayed answer may hide lost diagram/task structure → preserve independent component and visual gates.
- Timing/usage may be incomplete and prices absent → report observed values and unknown cost honestly.
- Lab ownership can change while planning → recheck the private schedule before acquisition; queue when occupied.
