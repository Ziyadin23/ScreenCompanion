# Proposal

## Why

Eight completed changes remain in the active OpenSpec list because closure was treated as a later action without an owner. The contributor completion checklist must make eligible closure part of the agent's accepted work and preserve genuinely unfinished work.

## What Changes

- Define the responsible agent's closure sequence in the existing contributor guide: verify requirements and tasks, assess and synchronize applicable specs, archive, repair links and validate the final tree.
- Preserve explicit user scope restrictions and record concrete reasons and next actions when a change must stay active.
- Inspect and archive the eight completed changes, retaining their historical records and repairing affected links.
- Keep the five incomplete changes active and close this documentation change through the same lifecycle.

## Capabilities

### New Capabilities

None. This changes contributor documentation and the location of completed records; `skip_specs: true` applies.

### Modified Capabilities

None. Application behavior and existing qualification limits are unchanged.

## Impact

The owning guidance is `docs/DEVELOPMENT.md`; `docs/STATUS.md` and references to relocated OpenSpec files require reconciliation. No application, tests, dependency, executable tooling, CI, release or lab changes are planned. [Issue #50](https://github.com/Ziyadin23/ScreenCompanion/issues/50) owns the agreed outcome; this change owns its detailed progress.
