# Proposal

## Why

New contributors currently enter through a user-focused README or a detailed maintainer workflow. The user requested a root `CONTRIBUTING.md` to make contributing easier to discover and follow.

## What Changes

- Add a short public guide covering issues, a fork/branch, setup, OpenSpec planning, checks and a focused PR.
- Explain the public contribution path and how maintainers coordinate private lab qualification, preserving existing privacy and verification rules.
- Link the entry point from README and the development guide; keep detailed policies in their existing owners.
- Validate navigation and document commands, then archive the completed documentation change with its checkpoint.

## Capabilities

### New Capabilities

None. This is contributor documentation.

### Modified Capabilities

None. Existing application capabilities and engineering policies are unchanged; `skip_specs: true` applies.

## Impact

Root `CONTRIBUTING.md`, README navigation, development-guide navigation/ownership, a status pointer and this OpenSpec owner. Application, tests, dependencies, build, CI policy, versions, releases, private lab state and existing unfinished task owners stay outside scope.
